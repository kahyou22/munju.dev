# 글 교정

글쓴이의 글에서 고칠 곳을 찾아 **제안만** 한다. 고르기 전에는 파일을 고치지 않는다.

## 대상

- 사용자가 고른 파일이나 글. 따로 말이 없으면 지금 이야기하는 글을 본다.
- 블로그 글이면 frontmatter의 `title`, `description`도 본다. 목록·검색·공유 미리보기에 그대로 보이는 글자다.

## 보는 것

1. **맞춤법**: 틀린 철자, 잘못 쓴 어미·조사 (예: 되/돼, 안/않, 로서/로써)
2. **띄어쓰기**: 의존 명사(것, 게, 수, 만, 데), 보조 용언, 단위 (예: "구현할게 적었으면" → "구현할 게 적었으면", "만들다만" → "만들다 만")
3. **용어 표기**: 고유한 대소문자와 점을 지킨다. JavaScript, TypeScript, GitHub, Next.js, Node.js, SvelteKit, macOS, iOS 등. 한 글 안에서 같은 말은 한 가지로 쓴다.
4. **문장 부호**: 짝이 맞지 않는 괄호·따옴표, 문장 끝 마침표가 섞여 있는지
5. **어색한 문장**: 뜻이 두 가지로 읽히거나 주어·서술어가 맞지 않는 문장. 고친 예를 하나 들되, 고를지는 글쓴이에게 맡긴다.
6. **MDX** (블로그 글일 때)
   - 쓰지 않는 `import`와 그 파일
   - 사이트 안 링크 끝의 `/` (예: `/posts/hello/`). 빠지면 개발 서버에서 404가 난다.
   - 이미지 `alt`가 비어 있지 않은지

## 건드리지 않는 것

- 코드 블록, 인라인 코드, 컴포넌트 속성 안의 코드, 주소(URL)
- 글쓴이의 말투와 문체(~다, ~요 등), 내용과 주장, 문단 구성
- 맞춤법상 둘 다 맞는 표현은 고치라고 하지 않는다. 꼭 말하고 싶으면 "선택"으로 따로 적는다.

## 보여주는 방법

고칠 곳을 번호를 붙여 한 번에 보여준다. 위치를 알 수 있게 줄 번호나 앞뒤 말을 적는다.

```
1. 12줄: "구현할게 적었으면" → "구현할 게 적었으면" (띄어쓰기: '게'는 '것이'의 준말인 의존 명사)
2. description: "만들다만" → "만들다 만" (띄어쓰기)
3. 20줄: "javascript" → "JavaScript" (용어 표기)
```

- 종류(맞춤법, 띄어쓰기, 표기, 문장, MDX)를 이유에 짧게 적는다.
- 고칠 곳이 없으면 없다고만 말한다.
- 그다음 어느 것을 반영할지 묻는다. 글쓴이가 고른 것만 그대로 바꾸고, 바꾼 내용을 다시 보여준다.
- 확실하지 않은 것은 "확인 필요"로 적고 이유를 말한다. 추측으로 단정하지 않는다.
